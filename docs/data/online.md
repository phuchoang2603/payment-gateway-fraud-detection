# Online data

The online path is live gateway traffic. The live simulator drives the gateway's public APIs at current time, Payments writes authoritative events that reach Kafka through outbox CDC, and a PyFlink job turns them into window features in Feast's online store, which Go Fraud reads in shadow mode. Bronze also ingests the same topics in Kafka mode; see [offline data](offline.md).

- Simulator code: [`src/data-pipeline/simulator/simulator/live`](../../src/data-pipeline/simulator/simulator/live). Streaming code: [`src/data-pipeline/streaming`](../../src/data-pipeline/streaming) and [`src/data-pipeline/feast`](../../src/data-pipeline/feast); deployment: [`infra/charts/fraud-features`](../../infra/charts/fraud-features).
- Status: the live simulator is disabled in both environments; the Flink job runs in dev in shadow mode and is disabled in prod. [PR #101](https://github.com/phuchoang2603/payment-gateway-fraud-detection/pull/101) reworks late arrivals, redelivery and the feature contract (v2: attempt starts keyed on client `attempted_at`, 5-minute, 1-hour and 24-hour windows, distinct devices over 24 hours); this page is updated with it.

## Data problems and how they are solved

| Problem | Generated by | Solved by | Evidence |
|---|---|---|---|
| Late arrivals | Store-and-forward clients hold an attempt and submit it later, carrying the original client `attempted_at` | Flink windows on attempt event time; attempts older than the longest window are counted and logged instead of updating state | Pending: configured versus observed lateness, Flink UI |
| Duplicates | Committed events are redelivered to the event topic, on top of at-least-once CDC | Flink deduplicates by event identity with bounded state; Bronze keeps every delivery and Silver deduplicates | Pending: configured versus observed duplicate rate |
| Restarts | Pod or node loss | Checkpoint recovery restores offsets and state; the Feast writer commits offsets only after reading back accepted writes | Bounded live verification restored a populated checkpoint |

## Live simulator

- Tokenizes synthetic cards, creates payments and submits attempts through Edge with run-scoped idempotency keys; retries reuse the same key and content.
- Publishes simulation-truth labels after each attempt and schedules chargebacks for successful fraud on `fraud.labels.v1`. Label availability is the actual publication time. The schedule is held in memory, so an interrupted run reports unfinished labels instead of claiming them.
- Configuration comes from `SIMULATOR_CONFIG`, rendered by the `live-traffic` chart.

The simulator continues the historical entity world: it rebuilds the world from the manifest's recorded configuration and checks the manifest's `world_digest` before sending anything.

## Streaming features

### Runtime

- Flink and PyFlink 2.2.1 on the platform's Flink operator, Kubernetes HA, checkpoints and savepoints in object storage under `runs/payment-gateway/flink/`.
- Parallelism one; each manager requests one CPU, the TaskManager 2 GiB.
- Each epoch has its own feature journal topic and state; a state layout change starts a fresh epoch instead of restoring incompatible state.
- The Feast writer runs as one replica, reads back accepted revisions, and only then commits Kafka offsets.

### Windows

Per-customer and per-method counts over `[t − window, t)` with explicit per-window coverage; missing history is null, never zero. Long 7- and 30-day windows are computed offline by DP3, not by Flink; there is no HybridSource bootstrap. See [feature store](../ml/feature-store.md).

Evidence (Flink UI captures, baseline versus handled late and duplicate cases, window code walkthrough) is added here with PR #101's acceptance.
