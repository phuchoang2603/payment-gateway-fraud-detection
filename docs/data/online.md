# Online data

The online path is live gateway traffic. The live simulator drives the gateway's public APIs at current time, Payments writes authoritative events that reach Kafka through outbox CDC, and a PyFlink job turns them into window features in Feast's online store, which Go Fraud reads in shadow mode. Bronze also ingests the same topics in Kafka mode; see [offline data](offline.md).

- Simulator code: [`src/data-pipeline/simulator/simulator/live`](../../src/data-pipeline/simulator/simulator/live). Streaming code: [`src/data-pipeline/streaming`](../../src/data-pipeline/streaming) and [`src/data-pipeline/feast`](../../src/data-pipeline/feast); deployment: [`infra/charts/fraud-features`](../../infra/charts/fraud-features).
- Status: the live simulator is disabled in both environments; the Flink job runs in dev in shadow mode and is disabled in prod. Dev simulator values point at the v18 historical manifest and its SHA-256. The Flink job implements feature contract v2 under epoch `live-v18`.

## Data problems and how they are solved

| Problem | Generated by | Solved by | Evidence |
|---|---|---|---|
| Late arrivals | Store-and-forward clients: a seeded share of attempts is held for a configured delay, then submitted with the original click time as `simulated_client.attempted_at` | Flink counts each attempt in the windows its `attempted_at` falls in, producing a new revision without changing served snapshots. Attempts older than the 24-hour horizon increment the `too_late` metric and are logged, without failing the job | Pending: configured versus observed lateness, Flink UI |
| Duplicates | Redelivery: a seeded share of committed events is re-published to `payments.events.v1` as byte-identical copies on the same partition, on top of at-least-once CDC | Flink deduplicates by `event_id`, dropping identical copies and failing on conflicting content; that state expires 25 hours after the attempt time, so a later copy is already too late. Bronze keeps every delivery and Silver deduplicates | Pending: configured versus observed duplicate rate |
| Restarts | Pod or node loss | Checkpoint recovery restores offsets and state; the Feast writer commits offsets only after reading back accepted writes | Bounded live verification restored a populated checkpoint |

## Live simulator

- Tokenizes synthetic cards, creates payments and submits attempts through Edge with run-scoped idempotency keys; retries reuse the same key and content.
- Publishes simulation-truth labels after each attempt and schedules chargebacks for successful fraud on `fraud.labels.v1`. Label availability is the actual publication time. The schedule is held in memory, so an interrupted run reports unfinished labels instead of claiming them.
- Configuration comes from `SIMULATOR_CONFIG`, rendered by the `live-traffic` chart.
- Store-and-forward lateness: `late_rate` (default 0) selects attempts held for `late_min_seconds`–`late_max_seconds` (300–600) and bounded by `max_held_attempts`. Edge accepts `simulated_client.attempted_at` only from synthetic integrations and rejects times after server time. Attempts still held at shutdown are reported as unsent.
- Redelivery: `redelivery.enabled` (default off) and `redelivery.rate` (0.015). Copies carry an `x-simulator-redelivery` header and are never copied again. Offsets commit after the copy is acknowledged, so a restart can add copies.

The simulator continues the historical entity world: it rebuilds the world from the manifest's recorded configuration and checks the manifest's `world_digest` before sending anything.

## Streaming features

### Runtime

- Flink and PyFlink 2.2.1 on the platform's Flink operator, Kubernetes HA, checkpoints and savepoints in object storage under `runs/payment-gateway/flink/`.
- Parallelism one; each manager requests one CPU, the TaskManager 2 GiB.
- Each epoch has its own feature journal topic and state; a state layout change starts a fresh epoch instead of restoring incompatible state.
- The Feast writer runs as one replica, reads back accepted revisions, and only then commits Kafka offsets.

### Windows

The job reads only `attempt_started` events, keyed on the client `attempted_at`; risk decisions do not gate contributions. Per-customer and per-method attempt counts over 5 minutes, 1 hour and 24 hours, plus distinct customer devices over 24 hours, cover `[t − window, t)`. Per-window coverage stays unknown until the job has run for that window's length, and missing history is null, never zero. An attempt time after its observed availability fails the job. Long 7- and 30-day windows are computed offline by DP3, not by Flink; there is no HybridSource bootstrap. See [feature store](../ml/feature-store.md).

Evidence (Flink UI captures, baseline versus handled late and duplicate cases, window code walkthrough) is added here when live traffic is enabled.
