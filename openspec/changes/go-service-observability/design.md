## Context

The five Go services live under `src/payment-gateway/` alongside a reusable shared module. Composition roots create slog JSON handlers independently. Payments and both simulators already attach `otelgrpc` server handlers; exporters/providers and consistent client instrumentation are absent. Payments/notifier own Prometheus registries, and simulators expose transport metrics. The platform collects stdout but has no complete application OTLP setup in this chart.

The current Python fraud service owns validation, two stateless rules, gRPC health, Prometheus metrics and opt-in OTLP tracing. It executes no model and needs no Python-specific runtime library for its business behavior. The target adds Go fraud as the sixth gateway service before applying the common telemetry contract. The `service-conventions` delta records the new language ownership and operational boundary.

The reference implementation is `refurbished-marketplace/shared/observe/{log,trace,metric}` plus `shared/runtime`, service composition roots, and its deployment annotations. It sends traces/metrics to the local agent and correlates stdout using `level`, `msg`, `trace_id`, `span_id` and the service-name pod annotation. Reuse the approach within this repository, without importing the marketplace module or copying its full runtime framework.

Payment events are immutable serialized protobuf bytes stored in `payment_events`, published by Debezium EventRouter to `payments.events.v1`, and consumed by notifier. There is no separate payment outbox. Notifier persists deliveries for later retries. Marketplace's EventRouter uses nullable `tracingspancontext` transport metadata and header propagation.

## Goals / Non-Goals

**Goals:** One bounded producer contract for all six Go services; request and asynchronous trace correlation including fraud decisions; useful RED/business metrics without a scrape service; inspectable results in shared HyperDX presets/explorers; business operation independent of exporter availability.

**Non-Goals:** Keeping or instrumenting the replaced Python fraud runtime, Feast/KServe deployment or client implementations before their use cases exist, Knative/autoscaling rollout, Spark/data workloads, telemetry platform deployment, extra collectors, custom dashboard JSON, profiling/session replay, logging payloads, or changing business event contracts. Do not instrument the Java KafkaConnect process as an application in this change; configuring and verifying existing CDC header propagation is in scope. Propagated Kafka context does not prove that Connect exports its own spans.

## Decisions

1. **Small shared Go helpers, service-owned lifecycle.** Put logging, tracing and metric provider helpers in `shared/observe`. Composition roots install providers before adapters/servers, pass contexts normally, and flush with independent bounded shutdown contexts. Domain packages remain free of telemetry dependencies. Reuse existing dependency versions where compatible and consult current SDK APIs during apply; avoid a repository-wide runtime rewrite.

2. **OTLP/gRPC for traces and metrics, stdout for logs.** Default trace export remains disabled and requires explicit enablement plus an endpoint, matching service conventions. Metrics similarly require explicit enablement/configuration. Deployment config enables both for the six services with `OTEL_SERVICE_NAME`, the agent endpoint, service-name annotations, a 60-second metric export interval and parent-based ratio sampling (initially 10% of new root traces). Tests use deterministic sampling. Always propagate valid W3C context independently of export enablement. Do not enable Go OTLP log export alongside stdout collection.

3. **One application metric path.** Replace application Prometheus instruments/listeners with OTLP business instruments and standard HTTP/gRPC RED metrics. Preserve the meaning of payment outcomes/attempt duration/recovery, notifier delivery outcomes/backlog/oldest pending age/consumption errors and simulator RPC metrics. Fraud records each decision once by outcome, counts reason matches separately, and distinguishes policy execution latency from full RPC latency. A decline is a successful business response, not an RPC error. Record a concrete old-name/new-name/unit/attribute mapping before removal, including the old Python fraud metrics; its reason counter may increment more than once per decision. Keep health/readiness listeners and remove the old fraud metrics listener. Avoid exporting the same application measurement via OTLP and scraping. Platform host/container metrics already cover process capacity; do not recreate every Go/process Prometheus collector by default.

4. **Trace boundaries follow actual transports.** Use route-template HTTP spans and supported gRPC stats handlers on both client and server sides, without adding duplicate handlers/interceptors. Instrument notifier's outbound HTTP transport without capturing payloads or sensitive headers. Use valid context-aware slog calls so active span identifiers become top-level fields; retain request IDs and use bounded/redacted structured fields. Suppress routine health probes. Domain IDs belong in bounded diagnostic context, never metric labels.

5. **Persist asynchronous transport context separately.** Add nullable `tracingspancontext` alongside new immutable payment event inserts, serialized using the marketplace's W3C Properties carrier for Debezium EventRouter. Never update existing ledger rows or alter `PaymentEvent` payload bytes. Configure EventRouter context-field/header handling and extract it from Kafka record headers. Forward the serialized Properties carrier explicitly as `tracingspancontext` through additional-field header placement so propagation works without a Connect tracing SDK; accept native W3C headers when present. Persist the needed context in notifier's delivery storage so restart/retry retains causality; retries get distinct attempt spans. Missing or invalid context starts a new consumer trace while retaining event/payment/request correlation. Do not propagate arbitrary user baggage or authentication material. Header routing and any new columns must be verified against the pinned connector, including tracing-disabled behavior; upgrade neither the connector protocol nor image unless that verification proves necessary.

6. **Reuse the platform UI contract.** Helm owns Go workload annotations/env only. No ServiceMonitor, application collector, UI credential, dashboard ConfigMap or app-owned HyperDX instance is added. The independent platform replacement restores `ecommerce` collection, retains `payment-gateway`, and provisions compatible telemetry sources. Marketplace Go services need no producer rewrite; its access/prerequisite documentation needs to match the restored public HyperDX endpoint.

7. **Replace fraud with an independent Go module.** Use `src/payment-gateway/fraud/cmd/fraud` as the composition root, with transport mapping/validation and pure domain policy. Retain the useful `fraud.v1` contract and current decision rules, including validation, version reporting, decline-as-OK and fail-closed unavailability at Payments. Adapt existing behavior tests to Go instead of maintaining two implementations. Use the shared Go image pattern and runtime helpers. Deploy all six Go services through the `infra/charts/payment-gateway` services map and its common templates, with independent Deployments and Services. Remove the dedicated fraud chart and Argo CD child; one gateway image pin covers all six Go images. Then remove `src/fraud-service`, its Dockerfile, unused Python bindings, dependencies and service-specific scripts/jobs/configuration. Preserve Python tooling used by simulation or future ML. Update the stale Python ownership/generated-path context in `openspec/config.yaml` during implementation. No runtime wrapper, dual rollout or legacy metric endpoint is required. This keeps independent policy deployment/scaling without merging decision ownership into Payments.

8. **Go coordinates later Feast and KServe calls directly.** When ML is introduced, add a use-case coordinator with bounded feature and model adapters. Go calls Feast's supported feature-server API for versioned features, then KServe's selected inference runtime, and applies pure policy to the result. Vendor protocol adapters may use HTTP/JSON where supported by Feast or HTTP/gRPC where supported by the chosen predictor; this does not create a parallel internal business API. Do not decode Feast's private Redis storage or add a custom Python coordinator. Python stays in Feast definitions/on-demand transformations, training and custom predictor preprocessing where needed. Keep model-specific transformations with the model artifact, version feature schemas/freshness/missing-value semantics and verify offline/online parity. Preserve authoritative decisions in Payments and publish monitoring from committed records. The separate Python-coordinator alternative embeds the SDK conveniently but adds an application runtime and duplicates orchestration ownership. Knative changes deployment/scaling, not these boundaries; select and verify runtime protocol support, deadlines, cold starts and warm minimum replicas during that later rollout.

The gateway chart resolves service defaults once through shared helpers. Image coordinates and the External Secrets store are shared; database ownership generates URL secrets and migration wiring, mounted Secret entries generate read-only volumes and file environment variables, and service ports/callers drive the corresponding probes and policies. Application pods use no persistent volumes. The chart refactor preserves rendered resource identities, effective configuration and security/storage behavior.

## Risks / Trade-offs

- [Sampled roots make some request waterfalls unavailable] → Preserve incoming sampling decisions, retain request/event correlation in logs and use full sampling only for bounded acceptance checks.
- [SDK or semantic-convention changes rename metrics] → Pin compatible versions and document the exported names actually read back from ClickHouse; verify presets against those results.
- [Async retries cross long delays and restarts] → Persist transport context independently of business bytes; test restart/replay and validate parentage or explicit links rather than infer continuity from IDs in messages.
- [Exporter outage consumes memory or delays shutdown] → Bounded queues, timeouts and independent flush budgets; readiness and payment/Kafka acknowledgements must not depend on successful export.
- [Trace data leaks payment secrets] → No body/query-string/header capture, payload-free database spans, targeted redaction tests and sensitive-value checks in a synthetic live flow.
- [Metric endpoint removal affects undocumented consumers] → Search chart/docs/scripts before removal, record the intentional change and coordinate deployed scrape configuration in the same rollout.
- [Go replacement changes validation or policy boundaries] → Reuse contract fixtures and decision-rule scenarios, including time, amount, missing-value and multi-reason cases; verify Payments still fails closed on unavailable fraud.
- [Future training/serving feature skew] → Keep versioned feature/model contracts and shared parity fixtures; introducing Go orchestration does not justify translating Python model transformations into Go.

## Migration Plan

Replace fraud with Go and update callers, code generation, CI, images and chart wiring together, removing the superseded Python runtime. Verify existing fraud behavior and health before enabling the common telemetry contract. Verify the shared HyperDX/agent/gateway is healthy and the target namespace is collected. Add helpers and instrument all six services. Add nullable transport metadata and deploy producer/CDC/consumer handling in that order; existing committed events remain consumable without metadata. Switch application metrics to OTLP and remove superseded scrape paths/listeners. Enable the charts after image CI and chart checks pass. Run a bounded synthetic payment/notification exercise, verify all six service identities and signal readback, then repeat with the exporter unreachable. Roll back via the prior release images/charts rather than maintaining parallel runtimes; nullable metadata columns can remain and telemetry tables are retained. Feast/KServe and their autoscaling are separate later rollouts.
